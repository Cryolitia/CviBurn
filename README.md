## Flake 输出

当前 `flake.nix` 提供两个 package：

```nix
packages.${system}.CviBurn
packages.${system}.usb_dl
```

### `CviBurn`

`CviBurn` 是本仓库的源码构建版本，它会：

1. 从源码编译主机端工具
2. 从 src/cv_dl_magic.S 生成 cv_dl_magic.bin
3. 校验 magic payload 与原始二进制一致
4. 把 magic payload 安装到 $out/share/CviBurn/cv_dl_magic.bin
5. 编译时把 MAGIC_PATH 写入程序
6. 安装可执行文件为 $out/bin/CviBurn

Nix 构建时会使用 unwrapped clang 生成 AArch64 裸机 magic payload，避免 Nix cc-wrapper 的 host hardening flags 混入交叉汇编流程。

### `usb_dl`

`usb_dl` 是从 Milk-V SDK tag `v2.0.1` 获取的上游预编译 Linux 二进制，用于参考、对照或必要时回退。

它不是由本仓库源码构建出来的程序。它的版权、许可和再分发条件归原始权利人或上游项目约束。该二进制本身是上游 Linux host 工具，通常只适合与其目标架构匹配的 Linux 环境；在非 x86_64 Linux 上未必可运行。

## 相较原始实现的改进

在传输层上，该实现放弃了原始实现中直接通过 libusb 抢占 USB endpoint 的方式，改为使用 Linux 内核已经提供的 `cdc_acm` 驱动，将设备作为 `/dev/ttyACM*` 字节流进行访问。目标设备本身枚举为 CVITEK “USB Com Port”，因此在 Linux 下走 ACM 后端更符合内核设备模型，也能避免用户态 libusb 与 `cdc_acm` 对同一接口的竞争。这样做之后，工具不再依赖 libusb，也不需要自行处理 USB interface claim、bulk endpoint 打开、kernel driver detach 等细节；该实现只负责 CVI 下载协议本身，包括 magic payload、FIP 传输、MGN1 flag、break、二阶段重连、CIMG chunk 和 `CVI_USB_PROGRAM` 等逻辑。换句话说，该实现将“USB 传输”交还给 Linux 内核，将用户态代码的关注点限制在协议状态机上。

在可维护性方面，该实现用维护良好、部署广泛的 Expat 替代了原始实现中脆弱的手写 XML 扫描逻辑，避免通过字符串查找和固定格式假设来解析分区清单。对于 `cv_dl_magic.bin` 这类关键 payload，该实现也不再把它作为不可审计的预置二进制文件直接保存，而是将其还原为 AArch64 汇编源，并在构建时生成 128 字节的 payload，再通过尺寸和校验值确认生成结果与预期一致。这样既保留了与原协议兼容所需的字节级行为，也让项目中的关键二进制内容具备可检查、可重建、可复现的来源。

在发行版集成方面，该实现针对 Nix/NixOS 做了专门整理。构建系统会在编译时把 `cv_dl_magic.bin` 的安装路径写入程序，避免原始实现依赖当前工作目录下 `fopen("./cv_dl_magic.bin")` 的行为；相比原始工具“放在某个目录里手动执行”的使用方式，该实现更适合纳入可复现构建、系统配置和开发板刷写工作流中。
